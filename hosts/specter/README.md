# specter — Lenovo ThinkBook 16 G7 QOY (Snapdragon X1P42100), Fedora 44 aarch64

What `install.sh` reproduces on this host, and what it cannot. Audited
2026-08-18 by asking: *if this machine were wiped and reprovisioned from this
repo, what would fail to come back?*

## install.sh reproduces these

| Thing | How |
|---|---|
| Speakers / HDMI audio | `install_asoc_topology()` — copies the ThinkPad T14s ASoC topology under this machine's filename into `/lib/firmware/updates` |
| Internal microphone | `install_ucm_mic_override()` → `tools/thinkbook16-mic-ucm.py` — this board's mic array is on a different DMIC bank than the T14s profile assumes |
| Prompt | `install_starship()` + the tracked `config/starship/starship.toml` |
| Monitor layout | `hosts/specter/kanshi/config` |
| sway / waybar / kitty / mako / foot | `link_configs()` |

Verify with `tools/doctor.sh` — it checks that capture actually returns samples
rather than trusting that a device exists.

## install.sh does NOT reproduce these

Listed worst-first. The first two are the difference between "boots" and
"does not boot at all".

### 1. `/boot/grub2/custom.cfg` — REQUIRED TO BOOT

Kept here as `boot/custom.cfg`. Fedora 44 embeds this laptop's DTB in the
kernel image but ships no CHID entry for it, so systemd-stub selects no device
tree and the machine resets within a second of GRUB handing off — with no
console output whatsoever. This file hands GRUB the DTB explicitly.

```bash
sudo cp hosts/specter/boot/custom.cfg /boot/grub2/custom.cfg
```

`custom.cfg` is sourced by `grub.cfg` and is *not* regenerated by
`grub2-mkconfig`, so it survives kernel updates. `/boot/dtb` is repointed to the
newest kernel's directory on install, and both installed kernels ship the
ThinkBook DTB — verified.

**Secure Boot must stay OFF.** GRUB disables the `devicetree` command under
lockdown, and the resulting failure is silent.

### 2. Kernel arguments

See `boot/kernel-cmdline`. These live in `/etc/kernel/cmdline` on Fedora, not
`/etc/default/grub` — editing the latter does nothing for new kernels.

### 3. Qualcomm firmware — cannot be committed

`/lib/firmware/qcom/x1p42100/LENOVO/21NH/` (12 files: GPU zap shader, ADSP,
CDSP, and their `.jsn` configs). Proprietary Lenovo/Qualcomm blobs extracted
from this machine's own Windows partition — redistributing them is not ours to
do, so only the procedure is documented, in
`SNAPDRAGON-FEDORA-FINDINGS.md` (Issue 5). Without the zap shader there is no
GPU acceleration. `restorecon` afterwards; Fedora enforces SELinux.

### 4. Other host-local state

- `~/.config/systemd/user/socks-lax01.service` — SOCKS tunnel for LAX01 BMCs.
  Deliberately out of this public repo: it names employer infrastructure.
- `~/.local/bin/dex` — a standalone Python script, owned by no package. Fedora
  does not package `dex`, which `sway/config` uses for XDG autostart.
- Flatpak: `flathub` remote (Fedora ships it *filtered*; `flatpak
  remote-modify --system --no-filter flathub`) and `com.google.Chrome`, which
  does have an aarch64 build.
- LUKS: the root volume is encrypted; its UUID is machine-specific.

## Known-broken / unresolved

- **Capture is mono.** Only DEC1 returns samples, so the left channel is
  digital silence. Both mics are individually readable but not simultaneously.
- `swayosd` is not packaged on Fedora; the sway config now guards its exec.
- HDMI was listed as needing kernel >= 7.0. This host runs 7.1.8 — untested since.
